### 3.2 工作流拓扑
```
parse_doc → split_clauses
```

## 十二、V4.0.6 管理员预置问题额度拦截修复（2026-06-29）

> **测试日期**: 2026-06-29
> **版本**: V4.0.6（管理员额度权限拦截修复版）
> **测试范围**: QA模块预置问题额度拦截Bug修复 + 前端端口调整 + 回归验证

### 12.1 问题描述

管理员账户登录后，在"法律问答"模块点击"预置问题"按钮时，系统错误弹出"今日咨询次数已达上限，请明日再试或升级套餐"提示，导致管理员无法使用预置问题功能。

### 12.2 根因分析

| 层级 | 逻辑 | 是否正确 |
|------|------|----------|
| 后端 `QuotaService.check_and_consume()` | 管理员返回 `(True, -1, -1)` 即放行、不限额度 | ✓ 正确 |
| 后端 `/qa/quota` API | 管理员返回 `remaining: -1` | ✓ 正确 |
| 后端 `/qa/ask/stream` API | 管理员不返回429，响应头 `X-RateLimit-Remaining: -1` | ✓ 正确 |
| **前端 `QA.vue` `handleSend()`** | `if (remainingQaQuota.value <= 0)` → 管理员 `-1 <= 0` 为 **true** → 错误拦截 | **✗ Bug根因** |
| **前端 `QA.vue` 流式回调** | `if (remaining <= 0)` → 管理员 `-1 <= 0` 为 **true** → 错误提示 | **✗ Bug根因** |

**根因**: 前端额度检查条件 `<= 0` 未排除管理员。管理员 `remainingQaQuota` 值为 `-1`（后端表示无限制），但 `-1 <= 0` 为 true，导致被错误拦截。V4.0.5 仅修复了额度**显示**（模板层），未修复额度**检查**（逻辑层）。

### 12.3 修复方案

| 文件 | 修改位置 | 修改内容 |
|------|----------|----------|
| `frontend/src/views/QA.vue` | `handleSend()` 额度检查（L500） | `if (remainingQaQuota.value <= 0)` → `if (!userStore.isAdmin && remainingQaQuota.value <= 0)` |
| `frontend/src/views/QA.vue` | 流式回调额度提示（L515） | `if (remaining <= 0)` → `if (remaining <= 0 && !userStore.isAdmin)` |
| `frontend/src/views/Contract.vue` | `handleUpload()` 额度检查（L840） | `if (remainingQuota.value <= 0)` → `if (!userStore.isAdmin && remainingQuota.value <= 0)`（预防性修复同类问题） |
| `docker-compose.yml` | 前端端口（L135） | `"${FRONTEND_PORT:-80}:80"` → `"${FRONTEND_PORT:-8080}:80"`（避免与Dify项目nginx端口80冲突） |

### 13.1 问题描述

1. **主题切换失效**: 登录成功后，点击顶部导航栏的主题切换按钮（画笔图标）无法弹出下拉菜单，功能完全无法使用。
2. **快捷登录需求**: 为方便测试，需在登录页添加三种角色（管理员/法务/普通用户）的一键快捷登录入口。

### 13.2 根因分析

| 问题 | 根因 | 影响 |
|------|------|------|
| 主题切换下拉菜单不弹出 | `el-dropdown` 内部嵌套了 `el-tooltip` 作为触发器。Element Plus 中 `el-tooltip` 会包裹内容并可能拦截点击事件，导致 `el-dropdown` 的 `trigger="click"` 无法正确触发 | 下拉菜单完全无法打开 |
| 主题切换视觉变化不明显 | `global.scss` 中多个关键组件（`.glass-card`、`.el-dialog`、`.el-dropdown-menu`、`.el-input`等）使用硬编码颜色 `rgba(15, 31, 56, ...)` 而非 CSS 变量 `var(--bg-card)`，导致即使 `data-theme` 属性切换了变量集，视觉上几乎无变化 | 用户感知不到主题变化 |

### 13.3 修复方案

#### 修复1：重构主题切换触发器（App.vue）

```html
<!-- 修复前：el-tooltip 嵌套在 el-dropdown 内，拦截点击事件 -->
<el-dropdown trigger="click" @command="handleThemeChange">
  <el-tooltip content="切换背景主题">
    <el-icon><Brush /></el-icon>
  </el-tooltip>
  ...
</el-dropdown>

<!-- 修复后：使用 div 作为触发器，title 属性替代 tooltip -->
<el-dropdown trigger="click" @command="handleThemeChange">
  <div class="theme-trigger header-icon theme-switch-icon" title="切换背景主题">
    <el-icon :size="20"><Brush /></el-icon>
  </div>
  ...
</el-dropdown>
```

将以下组件的硬编码颜色替换为CSS变量，确保主题切换时视觉同步变化：
