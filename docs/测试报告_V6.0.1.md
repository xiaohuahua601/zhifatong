## 〇、V6.0.2 增量修复：合同审查"合同内容为空，请先完成解析"

**现象**：管理员登录后进入合同审查，点击"开始审查/查看报告"弹出错误："合同内容为空，请先完成解析""审查失败，请重试"。

**修复方案**（[init_data.py](file:///../backend/app/init_data.py)、[contract_service.py](file:///../backend/app/services/contract_service.py)）：
1. 演示合同携带真实感合同全文（约 600 字，含试用期超限/竞业限制违约/无补偿解除等典型风险条款，审查可识别出风险）
2. "已审查"演示合同同步生成完整审查报告（评分 62.5/medium、3 条风险条款含法条依据、对抗式审查数据）
3. 合同种子独立幂等（`demo_contract_` 前缀标记），不受 `query_logs` 门控影响；存量环境启动自动补齐旧数据（已验证修复 6 条）
4. 多 worker 并发种子竞态保护：演示合同报告自动去重（保留最新一份）
5. `review_contract` 容错：历史合同 content 为空但源文件存在时自动重新解析

**验证结果**：

## 一、V6.0.1 修复与优化内容


### 1.1 缺陷修复：登录报"服务器内部错误，请稍后重试"

**现象**：使用 admin/admin123、lawyer/lawyer123、user/user123456 登录均返回 HTTP 500。

**根因分析**：
后端容器启动时（22:00:29），MySQL 刚进入健康状态但业务端口尚未完全就绪，建表与种子数据初始化失败（`Can't connect to MySQL server on 'mysql'`）。生命周期管理仅记录错误并继续启动，导致 `zhifatong.users` 等 16 张表全部缺失，登录查询抛出 `(1146, "Table 'zhifatong.users' doesn't exist")`，触发全局异常处理器返回 500。

**修复方案**（三处加固，已全部落地）：

| # | 修复点 | 文件 | 说明 |
|---|--------|------|------|
| 1 | 等待数据库就绪（指数退避重试） | `backend/app/main.py` | 建表前轮询 `SELECT 1`，最多 10 次约 60s，根治容器编排时序问题 |

| 3 | 种子重试覆盖连接类异常 | `backend/app/main.py` | 重试条件由仅"表不存在"扩展至"连接拒绝/无法连接" |

## 九、V6.0.3 缺陷修复：合同审查报"请求失败，请重试"（2026-08-27）

### 9.1 根因分析（双缺陷叠加）

| # | 缺陷 | 机制 |
|---|------|------|
| 1 | **前端 30s 超时** | 审查接口沿用全局 axios `timeout: 30000`，而多Agent审查含多次 LLM 调用实测耗时 41s+，前端必然超时报"请求失败，请重试"（后端实际仍在正常执行） |
| 2 | **后端长事务持锁** | `review_contract` 中 flush 置 `REVIEWING` 后**未提交**，持 contracts 行锁跑完整个 LLM 审查（数十秒）；用户点"关闭重试"→ 新事务 UPDATE 同一行 → 锁等待 50s → MySQL 1205 超时 → 二次失败 |

### 9.2 修复内容

1. **事务边界拆分**（[contract_service.py](file:///e:/临时项目/3_大模型项目_实施/项目1_智法通_企业级智能法律顾问平台/backend/app/services/contract_service.py)）：
   - 状态置 `REVIEWING` 后立即 `commit` 释放行锁，LLM 审查期间不持有任何数据库事务
   - 审查结果（报告+风险条款+`REVIEWED` 状态）在同一事务原子提交
   - 失败路径：先 `rollback` 清残留，再以独立事务回写 `FAILED` 状态
2. **并发防抖**：合同处于 `REVIEWING` 时拒绝重复发起，返回"该合同正在审查中"（消除锁冲突源头）
3. **API 错误语义**（[contract.py](file:///e:/临时项目/3_大模型项目_实施/项目1_智法通_企业级智能法律顾问平台/backend/app/api/contract.py)）：业务校验异常转 HTTP 400 + 具体 detail（此前为 500"服务器内部错误"，用户无法得知真实原因）
4. **前端超时与提示**（[contract.ts](file:///e:/临时项目/3_大模型项目_实施/项目1_智法通_企业级智能法律顾问平台/frontend/src/api/contract.ts)、[Contract.vue](file:///e:/临时项目/3_大模型项目_实施/项目1_智法通_企业级智能法律顾问平台/frontend/src/views/Contract.vue)）：审查请求单独 5 分钟超时；失败提示透传后端具体原因

## 十、V6.0.4 优化：审查报告三维度评分/修改建议/进度动画（2026-08-27）

### 10.1 用户反馈问题与根因

| # | 现象 | 根因 |
|---|------|------|
| 1 | 完整性/合规性/一致性恒为 0%（无论综合评分是否为 0） | ① 后端将 **JSON dict**（如 `{"completeness_ratio":0.57}`）存入维度字段，前端 `parseInt` 解析 NaN→恒 0；② 小模型 qwen2.5:1.5b 返回畸形评分 0 污染 `min()` 合并逻辑；③ 扣减公式"每问题-5分无下限"，问题数≥14 即归 0 |
| 2 | 综合评分为 0 时"修改建议"为空 | 工作流条件路由 `risk_score≥80 → 跳过建议生成节点`，极高风险合同反而没有建议 |
| 3 | 审查进行中进度动画观感差 | 进度模拟 4 秒冲到 100% 后僵死等待（真实审查 40-70s），后段进度条无变化像"卡住" |
| 4 | （连带发现）重新审查后"查看报告"500 错误 | 重新审查产生多份报告，`scalar_one_or_none()` 遇多行抛 "Multiple rows" |
| 5 | （连带发现）摘要显示"包含敏感内容，无法生成摘要" | 小模型对合同文本内容审核过敏，推脱文本被当作正常摘要入库展示 |

### 10.2 修复内容

1. **维度分存数值**（[contract_service.py](file:///e:/临时项目/3_大模型项目_实施/项目1_智法通_企业级智能法律顾问平台/backend/app/services/contract_service.py)）：三维度字段改存数值分数字符串（各检查节点产出的 0-100 顶层评分）；种子数据同步统一格式
2. **LLM 评分有效性校验**（[nodes.py](file:///e:/临时项目/3_大模型项目_实施/项目1_智法通_企业级智能法律顾问平台/backend/app/agent/nodes.py)）：完整性/合规性/一致性三节点的 LLM 评分仅在有效区间 (0,100] 时参与合并，畸形分（0/负数）回退规则引擎分/基准分

## 十一、V6.0.5 修复：综合评分 0 与维度分非 0 的逻辑矛盾（2026-08-27）

### 11.1 用户反馈问题与根因

用户指出：软件技术培训服务合同、兼职教师聘任合同、合作协议审查三份合同**综合评分 0 分，但完整性/合规性/一致性均非 0%**，逻辑上自相矛盾。

根因：`calculate_risk_score` 节点中 `overall_score = 100 - risk_score`。风险分由四项加和（风险条款×10 + 合规问题×15 + 一致性问题×8 + 完整性缺失×20）极易封顶 100，综合评分被强制归 0，与维度分完全脱钩。

### 11.2 修复方案：维度加权融合评分

综合评分 = **维度健康分 × 0.5 + 风险安全分 × 0.5**，其中维度健康分 = 完整性×0.3 + 合规性×0.4 + 一致性×0.3。

数学性质保证：
1. 维度任一非 0 → 综合非 0（消除"维度非 0 但综合 0"的矛盾）
2. 风险越高综合越低（单调性保持，高风险合同仍得极低分，风险等级仍由 risk_score 独立判定为 critical）
3. 全维度满分且无风险 → 综合 100（上限保持）

### 11.3 连带修复（验证过程中发现）

| # | 问题 | 修复 |
|---|------|------|
| 1 | `generate_report` 兜底公式引用未定义变量（NameError 风险） | 维度读取移至使用前 |
| 2 | 小模型把"原条款文本"填入建议 `suggestion` 字段（建议=原文，无价值） | 风险/合规两段建议均增加有效性后处理：与原文相同/互为子串/过短 → 规则化重组（明确指出风险类型+等级+描述+修订指引） |
| 3 | LLM 误报"无风险"条款生成自相矛盾建议 | 误报条目直接剔除 |
| 4 | 建议数量随机波动（1~12 条）、存在重复与双句号 | 按文本去重+标点清理+不足 3 条时规则化补齐（风险条款/缺失条款/合规问题三类兜底） |

**Markdown 文档结构**（精美专业）：
- 头部：`# 合同名` + 引用块封面（智法通·合同优化版标识、原始评分、风险等级、生成时间、修订统计）+ 分隔线
